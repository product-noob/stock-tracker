When critiquing a design/product doc, apply the fixes directly using best judgement. Do not hand back
"decision blocks" for the user to pick between.

**Why:** On the Stock Market product note (2026-08-22) I offered to apply cosmetic fixes and leave the three
structural contradictions as flagged choices. Prince answered the two he cared about and said
"you use your best judgement to update the html with the right set of improvements" — he wants the doc
moved forward, not a menu.

**How to apply:** Decide, write it into the doc, and record the assumption in an explicit
"Open Questions" section with how it would be resolved (measurement vs owner decision) and what it blocks.
Also keep a Change Log section stating what changed *and why the old version was wrong* — he engages with
the reasoning, not just the diff. Empirically verifying claims in the doc (curl the feed, count the items)
before critiquing is what made the critique land — keep doing it.
