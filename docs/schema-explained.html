1️⃣ What does this system even do?

Every day, Indian stock exchanges (NSE & BSE) publish hundreds of company announcements. Some are boring; a few matter a lot — a big order win, a dividend, a regulatory probe, a fundraising. This system automatically collects those announcements, understands them with AI, checks how the stock price reacted, and sends you a short daily digest of only the important stuff.

💡 One-sentence summary

The database doesn't just store results — it stores the full evidence trail, so any insight we ever send you can be traced back to the exact bytes of the original announcement.

2️⃣ The 7 schemas — think of them as filing cabinets

A PostgreSQL database can contain multiple schemas — think of them as labeled drawers in one big filing cabinet. Each drawer belongs to one job in the pipeline.

core

🗂️ Who exists?

The master list: companies we track, their shares (instruments), where they trade (listings on NSE/BSE), alternative names (aliases) and whitelist membership history.

  • companies · instruments · listings
  • company_aliases · whitelist_memberships
  • reference vocabularies (ref_sources…)
platform

⚙️ What needs doing?

A built-in to-do list and message board. Long-running steps (download this PDF, run AI on that text) become jobs here, and finished work announces itself via the outbox.

  • processing_jobs — retryable task queue
  • outbox_events — reliable hand-off messages
ingestion

📡 What did we fetch?

The intake desk. Every poll of an RSS feed or API, the exact raw response, parsed items, cleaned-up canonical records, and which company each record belongs to.

  • source_partitions · fetch_runs · cursors
  • raw_artifacts · raw_feed_items
  • normalized_records · identity_resolutions
  • stage_runs · stage_errors
documents

📄 What did we download?

The archive room. Every downloaded PDF/article is fingerprinted (SHA-256) and stored once. Extracted text is versioned — re-running a better extractor adds a version, never overwrites.

  • content_objects — immutable files registry
  • content_fetch_attempts — incl. failures
  • record_contents · text_versions
intelligence

🧠 What does it mean?

The brain. AI reads the documents, extracts business events (results, dividends, order wins…), groups related mentions into events, snapshots each grouping, and produces scored insights.

  • extractions · extracted_event_mentions
  • events · event_versions (immutable)
  • insights · reaction_signals
market

📈 How did the price move?

The market tape. Price history belongs to a specific listing (e.g., NSE:HDFCBANK) with a fixed adjustment mode, so adjusted and raw prices never get mixed up.

  • price_series — one definition per series
  • price_bars — OHLCV observations
  • current_price_bars view
delivery

📬 What did we send you?

The post office. Daily digests, their ranked contents, the exact rendered notification messages, and one row per delivery attempt (including failed retries).

  • digests · digest_items
  • notifications · delivery_attempts

4

Instead of downloading immediately, the system enqueues a durable job — if the server crashes mid-download, the job survives and retries:

💡 Jobs use idempotency keys (job_kind + idempotency_key unique), so the same download request can safely be enqueued twice — only one job will exist.

4️⃣ The golden rules of this database 📜

  • 🔒 Evidence is append-only. Raw artifacts, downloads, extractions, event snapshots, price bars and delivery attempts cannot be updated or deleted — database triggers physically block it.
  • 🧾 Corrections = new versions, never edits. Better extractor? New text_version. Re-cluster? New event_version that supersedes the old one.
  • 🔑 Idempotency everywhere. Almost every insertable row has a stable idempotency key — feeding the same input twice inserts once. Safe retries by design.
  • 🧬 Every output remembers its inputs. Insights store fingerprints, model versions, rulepack versions and pointers to the exact text they were computed from.
  • 🏢 Company ≠ instrument ≠ listing. Prices belong to listings; events belong to companies; aliases may be ambiguous and the resolver fails closed rather than guessing.
  • 🗃️ Bytes live in object storage; the DB registers them. SHA-256 + storage path make every fetched document replayable forever.
